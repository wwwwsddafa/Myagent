## 二、创建虚拟环境

```bash
# 进入项目根目录
cd agents

# 创建虚拟环境
python -m venv venv

# 激活（Windows）
venv\Scripts\activate
# 激活（macOS / Linux）
source venv/bin/activate
```

## 四、API Key 申请

### 4.1 清单

| Key | 用途 | 用在哪 | 免费额度 |
|---|---|---|---|
| **LLM API Key** | 大模型推理 | 全部项目 | 见下方说明 |
| **Tavily API Key** | 联网搜索（专为 AI 优化） | notebooks、autoGen-test、Pro1、Pro2 | 注册即送额度，够学习用 |
| **SerpApi Key** | Google 搜索（经 SerpApi 代理） | 仅 `ch4/search.py` | 每月 100 次免费 |
| **Embedding API Key** | 文本向量化 | 仅 Pro2 的 RAG | 见下方说明 |

> `wttr.in` 天气 API 和 `arXiv` API **无需注册**，直接调用即可。

### 4.2 大模型接入（二选一）

项目用的是 **OpenAI 兼容协议**，所以任何提供该协议的厂商都能接。

**方案 A：ModelScope（魔搭，推荐入门）**
- 地址：https://modelscope.cn
- 注册后在个人中心获取 API Key
- 支持的模型如 `Qwen/Qwen3.5-35B-A3B`
- `base_url` 形如 `https://api-inference.modelscope.cn/v1/`

**方案 B：阿里云百炼 DashScope（MaaS）**
- 地址：https://bailian.console.aliyun.com
- 文本模型与 Embedding 模型可一起搞定
- `base_url` 形如 `https://xxxx.cn-beijing.maas.aliyuncs.com/api/v1`

> 本仓库的 LLM 用方案 A，Embedding 用方案 B（Pro2 的 RAG 需要）。你也可以统一成一家。

### 4.3 申请 Tavily
- 地址：https://tavily.com
- 注册后在 Dashboard 拿 API Key
- 它是专为 LLM/Agent 设计的搜索 API，返回值本身就是"整理好的答案"，比直接爬网页省事得多

## 五、配置 `.env`

仓库里有两处 `.env`，**都在 `.gitignore` 中，不会上传**。

### 5.1 位置一：仓库根 `data/.env`

供 `ch4`、`notebooks`、`autoGen-demo`、`autoGen-test`、`Pro1` 使用。

```env
# ---------- 大模型 ----------
OPENAI_API_KEY=sk-你的密钥
OPENAI_BASE_URL=https://api-inference.modelscope.cn/v1/
MODEL_NAME=Qwen/Qwen3.5-35B-A3B

# ---------- 搜索 ----------
TAVILY_API_KEY=tvly-你的密钥
SERPAPI_API_KEY=你的密钥
```

> `autoGen-demo` / `autoGen-test` / `Pro1` 也识别 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL_ID` 这组别名，二选一即可。

### 5.2 位置二：`src/ch6/langgraph/Pro2/.env`

Pro2 额外需要 Embedding 配置。

```env
# ---------- 大模型 ----------
LLM_API_KEY=sk-你的密钥
LLM_BASE_URL=https://api-inference.modelscope.cn/v1/
LLM_MODEL_ID=Qwen/Qwen3.5-35B-A3B
LLM_TIMEOUT=60
LLM_TEMPERATURE=0

# ---------- Embedding（RAG 用）----------
EMBED_API_KEY=sk-你的密钥
EMBED_BASE_URL=https://你的端点/api/v1
EMBED_MODEL_NAME=Qwen3.7-Text-Embedding

# ---------- 搜索 ----------
TAVILY_API_KEY=tvly-你的密钥
```

### 5.3 ⚠️ 已知坑位

#### 坑 1：三个项目找不到 `.env`

`autoGen-demo`、`autoGen-test`、`Pro1` 的 `_load_env()` 函数会打印：

```
⚠️ 未找到 .env 文件，尝试从系统环境变量读取
```

**已修复**：`_load_env()` 已改为从脚本所在目录**向上逐层搜索**仓库根 `data/.env`，无论在哪一层运行都能自动定位，无需手动复制或改代码。

**历史 workaround（仓库已修复，以下供参考）**：

```bash
# 方法 A：直接设系统环境变量（最快，不改代码）
# Windows
set OPENAI_API_KEY=sk-xxx && set OPENAI_BASE_URL=https://... && set MODEL_NAME=Qwen/...
# macOS / Linux
export OPENAI_API_KEY=sk-xxx

# 方法 B：把 .env 复制到项目自己的目录下
# 例如复制到 src/ch6/langgraph/Pro1/.env

# 方法 C：改 _load_env() 的 possible_paths，多往上找一层
```

#### 坑 2：notebooks 曾硬编码作者机器路径（已修复）

两个 `.ipynb` 里写了：

```python
load_dotenv(r"c:\Python_Ai\agents\data\.env")   # ← 这是原作者的机器路径
```

**已修复**为从当前工作目录向上逐层查找仓库根 `data/.env`，换机器无需改动（原先写死为他人机器路径）：

```python
from dotenv import load_dotenv
load_dotenv("../../data/.env")   # 相对路径
```

#### 坑 3：必须在正确的目录下运行

因为用了 `from tools import ...`、`from llm import ...` 这类**同级模块导入**，所以工作目录必须是脚本所在目录：

```bash
cd src/ch4                        # 然后 python react_agent.py
cd src/ch6/autoGen-test           # 然后 python travel_assistant.py
cd src/ch6/langgraph/Pro2         # 然后 python main.py
```

不在对应目录下运行会报 `ModuleNotFoundError`。

#### 坑 4：Pro1 导入就抛异常

`Pro1/askAssistantAgent.py` 在**模块顶层**就创建 LLM 客户端，拿不到 Key 会直接 `raise ValueError`。这是设计如此（快速失败），配好 `.env` 即可。

#### 坑 5：AutoGen 的 ModelInfo 警告

```
UserWarning: Missing required field 'structured_output' in ModelInfo.
```

无害，只是 AutoGen 提示未来版本会要求这个字段。想消除的话在 `model_info` 字典里补一项 `"structured_output": False`。
